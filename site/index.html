Lass einen Affen auf deine Testumgebung los

Ein Kommandozeilenwerkzeug, das mit Playwright einen echten Browser steuert, sich mit Seed-gesteuertem Zufall klickend, tippend und absendend durch deine Website bewegt und meldet, was kaputtgeht: nicht abgefangene Fehler, fehlschlagende Requests, kaputte Seiten. Zu jedem Befund gibt es die Schritte zum Nachstellen.

Stand: Version 0.8.0. Der Zufalls-Monkey mit Seed, mit Orakeln, Berichten, Baseline, Replay und Shrink; Claude auf Microsoft Foundry oder jeder OpenAI-kompatible Endpunkt für festgefahrene Situationen, auf Wunsch als Agent, mit geschwärzten Screenshots und als Orakel für visuelle Fehler; Cookie-Banner, native Dialoge, iframes, Popups, Uploads und Downloads werden behandelt; parallele Läufe je Rolle und Seed und ein CI-Beispiel.

Was PlayMonkey für dich tut

Zufalls-Monkey mit Seed

Klickt Links und Buttons, füllt Formulare mit gültigen und fiesen Werten und erkundet unbesuchte Zustände. Derselbe Seed ergibt denselben Lauf.

Ein LLM nur, wenn er feststeckt

Cookie-Banner, Dialoge, Formulare, die gültige Daten brauchen, oder eine Anmeldeschranke: Ein Modell übernimmt für ein paar Schritte, dann macht der Monkey weiter.

Befunde statt Rauschen

Orakel achten auf nicht abgefangene Exceptions, Konsolenfehler, HTTP 4xx und 5xx, Abstürze, Hänger, Fehlerseiten, Layout-Überlauf und auf Wunsch Barrierefreiheit, ohne Duplikate. Mit einer Baseline lassen nur neue Befunde die CI scheitern.

Reproduzierbar von Grund auf

Jede Aktion wird mit einem dauerhaften Locator protokolliert. monkey replay spielt das Protokoll ohne LLM erneut ab, monkey shrink kürzt den Weg zu jedem Befund auf die wenigsten Aktionen; Traces und Videos zeigen, was passiert ist.

Gebaut für Testumgebungen

PlayMonkey klickt, löscht und sendet alles ab, was es findet. Richte es nur auf Umgebungen, die du zurücksetzen kannst.

  • Bewusst ohne Schutzgeländer. Es gibt keinen Nur-Lese-Modus und keine Bestätigung; genau so findet es die Fehler.
  • Läufe enden immer. maxSteps und maxMinutes beenden jeden Lauf.
  • Es bleibt auf deiner Website. Mit stayOnDomain (standardmäßig an) folgt es keinen Links zu anderen Origins.
  • Secrets kommen aus der Umgebung. ${VAR}-Platzhalter werden beim Start aufgelöst und in jeder Ausgabe als *** maskiert.
  • Jede Rolle ist isoliert. Jede Anmeldung läuft in ihrem eigenen Browserkontext; Cookies gelangen nie von einer Rolle zur anderen.

Mehr zu den Grundregeln

In drei Schritten loslegen

Du brauchst Node.js 26 oder neuer und einen Playwright-Browser. Beschreibe die Website in einer JSON-Konfiguration; Secrets bleiben in Umgebungsvariablen.

{
  "baseUrl": "https://test.example.org",
  "auth": [
    {
      "name": "admin",
      "loginUrl": "/login",
      "fields": { "username": "${ADMIN_USER}", "password": "${ADMIN_PASS}" },
      "submit": "button[type=submit]"
    }
  ]
}
  1. Installieren. npm install --save-dev github:besessener/PlayMonkey#v0.8.0 in deinem Projekt, danach npx playwright install chromium.
  2. Konfigurieren. Schreibe eine Konfiguration wie die obige und exportiere die Variablen, auf die sie verweist.
  3. Starten. npx monkey run config.json meldet sich an, erkundet jede Rolle und listet die Befunde auf, jeden mit Screenshot und den Schritten, die zu ihm geführt haben.

Das Tutorial Erste Schritte führt dich gegen die mitgelieferte Fixture-Seite durch alles; die Konfigurationsreferenz listet jeden Schlüssel auf.
